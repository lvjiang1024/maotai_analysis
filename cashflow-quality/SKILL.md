# 现金流质量分析

利润表可以修饰，现金流量表很难。这个技能做的是一件事：**验证账面利润有没有真金白银支撑**。

## 四个核心指标

| 指标 | 公式 | 看什么 |
|------|------|--------|
| **收现比** | 销售商品提供劳务收到的现金 ÷ 营业收入 | 卖出去的货有没有收到钱。含税收现通常 >100%（含增值税），持续 <100% 说明大量赊销 |
| **净现比** | 经营活动现金流量净额 ÷ 归母净利润 | 赚的利润有没有变成现金。长期 <100% 说明利润是纸面富贵 |
| **现金去向** | 现金余额 / 资本开支 / 现金分红 | 挣的钱是躺在账上、投出去了、还是分给了股东 |
| **有息负债** | 短期借款+长期借款+应付债券+一年内到期非流动负债 | 是靠自身造血还是靠借钱运转 |

**判读要点**：单看一年意义不大，要看趋势和背离。经营现金流长期低于净利润，通常意味着
应收账款或存货在膨胀；某一年现金流远超利润，往往是预收款（经销商打款）大增——
对白酒、地产等预收模式行业是需求旺盛的信号。

## 使用流程

### 第一步：提取数据

```bash
pip3 install pdfplumber
# 从仓库直接跑
python3 cashflow-quality/scripts/extract_cashflow.py <年报目录> --company <公司名>
# 若已装为个人技能（见文末「安装」）
python3 ~/.claude/skills/cashflow-quality/scripts/extract_cashflow.py <年报目录> --company <公司名>
```

脚本自动扫描目录下文件名含 4 位年份及「年报/财报/年度报告」的 PDF（自动排除季报、
半年报），逐份提取全部科目，输出 `<公司名>_现金流数据.json`，并在终端打印
逐年汇总表和缺失项清单。

常用参数：
- `--years 2020 2021 2022` 只跑指定年份（调试时用，全量跑 25 份约需 2–3 分钟）
- `--out path.json` 指定输出路径

### 第二步：核对数据

**不要跳过这步。** 跨年度报表格式差异极大，脚本已处理了主要陷阱，但换一家公司
仍可能出现新情况。至少做这两项检查：

1. **看脚本输出的缺失项清单**——任何 `⚠️` 提示的年份都要翻开该年年报人工核对。
2. **交叉校验**——若项目里已有其他来源的财务数据（如既有的 quarterly_data.json），
   比对营收/净利润/经营现金流是否一致；若能拿到相邻年份年报，用「本期数」与次年
   年报「上期数」做勾稽。

不一致时以年报原文为准，并在报告脚注写明口径。

### 第三步：生成图表

图表 JS 模板与配色见 `references/charts.md`，含四张标准图的完整 Chart.js 配置，
可直接嵌入既有 HTML 报告的新 Tab。

## 跨年度格式差异——务必先读

这些坑是在贵州茅台 2001—2025 共 25 份年报上逐一踩过并修正的。A 股报表格式演变是共通的，
换一家公司大概率会遇到同样的问题。**修改提取逻辑前先读这段，能省掉大量重复排查。**

| 陷阱 | 表现 | 处理方式 |
|------|------|---------|
| **正文误匹配** | 董事会报告里也讨论「销售商品、提供劳务」等科目，按关键词首次出现会抓到正文而非报表 | 正式报表恒在「财务报告」章节即文档后段，先按位置排除前 25%，再取首个命中 |
| **合并 vs 母公司** | 同一科目在合并报表和母公司报表各出现一次，取错会小一大截 | 合并报表恒排在母公司报表之前，取首个命中即可 |
| **列序颠倒** | 2007 年前老式资产负债表是「年初数 期末数」，与新式「期末余额 年初余额」相反，直接取第一个数会拿到年初值 | 按表头文字出现顺序判断 |
| **粗体标题字符重复** | 部分 PDF 的粗体标题被 pdfplumber 提取成「合合合合并并并并」 | 匹配前做重复字符折叠 |
| **净利润口径** | 老式利润表「五、净利润」已扣少数股东损益即归母；新式「四、净利润」含少数股东损益 | 优先取「归属于母公司…净利润」行，注意排除「…综合收益总额」 |
| **标签带前后缀** | 归母行可能写作「1.归属于母公司股东的净利润（净亏损以"-"号填列）」，精确匹配和前缀匹配都失效 | 用谓词匹配：含「归属于母公司」+「净利润」且不含「综合收益」 |
| **营业总收入 ≠ 营业收入** | 并表财务/金融子公司的集团，利润表为「一、营业总收入」下挂「其中：营业收入」，总收入含利息及手续费收入 | 销售收现对应的是营业收入，优先取「其中：营业收入」 |
| **现金余额口径断层** | 并表财务公司后，大量资金列示于「存放中央银行款项」而非「货币资金」，沿用货币资金口径会出现失真断崖（茅台 2019→2020 表现为 1220 亿→361 亿） | 统一采用现金流量表「期末现金及现金等价物余额」；老式报表无该行时才回退货币资金期末数 |
| **跨页报表** | 利润表常与资产负债表尾部同页，且科目跨 2–4 页 | 定位到首页后连读 3–4 页的表格行 |

## 口径说明必须写进报告

只要用了回退或替代口径，就要在图表下方写明，否则读者无法判断数据可比性。至少说明：

- 现金余额采用的是哪个口径、为什么（尤其涉及财务公司并表时）
- 净利润是归母还是含少数股东
- 有息负债的构成科目
- 哪些年份的数据来自回退逻辑

## 输出文件

- `<公司名>_现金流数据.json`：逐年原始科目 + 派生比率，便于复用与复核
- 图表 JS 数组：由 JSON 转换而来，嵌入 HTML 报告

## 改动脚本后必须跑回归自测

提取逻辑高度依赖各年报表的具体排版，改一处匹配规则很容易在别的年份引发静默错误——
不是报错，而是悄悄取到相邻科目（如把「营业总收入」当成「营业收入」，或把含少数股东的
净利润当成归母净利润）。这类错误肉眼几乎看不出来，只有回归测试能拦住。

```bash
python3 cashflow-quality/tests/test_extraction.py          # 快速：只跑历史出过问题的年份，约 30 秒
python3 cashflow-quality/tests/test_extraction.py --full   # 完整：25 份年报全跑，约 3 分钟
```

基准值 `tests/baseline_贵州茅台.json` 逐年与年报原文核对过。测试会：

- 比对 8 个科目，偏差超过 0.015 亿即报错，并指出该年对应的格式陷阱
- 区分「数值不对」与「完全提取不到」（后者通常意味着定位逻辑被改坏）
- 检查恒等式 `销售收现 ≥ 营业收入`（含税收现恒高于不含税营收，反了说明取到了母公司报表）

退出码 0/1，可直接用于 CI。改动定位或匹配逻辑后建议跑 `--full`。

基准 PDF 随 maotai_analysis 仓库分发。若技能已装到 `~/.claude/skills`，
用 `--pdf-dir` 指向仓库里的年报目录：

```bash
python3 ~/.claude/skills/cashflow-quality/tests/test_extraction.py \
  --pdf-dir /path/to/maotai_analysis/财报
```

**新发现格式问题时**，把对应年份补进 `test_extraction.py` 的 `REGRESSION_YEARS`
并附上一句陷阱说明，让它永久受测试保护。
